## 1. 文档说明

本文是立项级需求规格，不是实现手册。目标是把「做什么 / 不做什么 / 做到什么程度 / 交互长什么样 / 系统怎么拆」一次说清，后续可直接拆 Epic、接口契约和迭代计划。

你已明确的硬约束：

1. 不需要登录。
2. 界面参考 Cursor。
3. 可自定义、可插拔 Skill。
4. 可自定义添加 LLM。
5. 流式输出；消息按类型分类渲染（工具调用、文件编辑等）。
6. 技术栈锁定：Python 3.11 + FastAPI + TortoiseORM + LangGraph；Vue 3 + TypeScript + OpenTiny（TinyVue）+ TinyRobot。
7. 交互式终端（PTY）为必做。
8. 刷新页面后，进行中的对话必须继续输出。
9. 配置与能力尽量可插拔，用户自定义度优先。
10. 工作台各窗口可拖动重新排版，布局可持久化。

## 2. 产品愿景与问题定义

### 2.1 愿景

让开发者用浏览器打开一个本地/私有部署的工作台，就能像用 Cursor 一样：对着真实代码仓库说话、看 Agent 思考与动手、审查 diff、插拔 Skill、自备模型。数据和密钥默认留在自己机器上。

一句话：**开源的 Web 端编码 Agent 工作台，而不是又一个聊天框套壳。**

### 2.2 要解决的问题

| 痛点 | 现状 | Code Agent 的回答 |
| --- | --- | --- |
| Cursor / Copilot 闭源、绑定账号与云 | 能力强但不可自控 | 开源、可自托管、无强制账号 |
| 开源 Chat UI 不会改代码 | 只会对话，没有工作区与 diff | 工作区 + 工具 + 分类渲染 + 可审查变更 |
| 编码 Agent 难扩展 | Prompt 写死、工具写死 | Skill 插拔 + LLM 插拔 + 工具权限策略 |
| 流式过程不可读 | 一大段 token 糊在一起 | 事件协议 + 分类型消息块 |
| 企业/个人密钥不敢上云 | SaaS 代扣 | 本地配置、默认不登录、密钥本机加密存储 |

### 2.3 产品原则

1. **工作区是一等公民**：Agent 围着一个真实目录工作，而不是抽象会话。
2. **过程可见、结果可审**：每一步工具、每次改文件都可展开、可对照、可拒绝。
3. **默认安全，可显式放开**：无登录 ≠ 无防护。默认只监听本机、命令需策略、密钥不明文落盘。
4. **协议优于实现**：流式事件、Skill 目录、LLM Provider 都是稳定契约，UI 和图可以换。
5. **渐进披露**：Skill、规则、索引都按「先元数据、后全文」加载，控制上下文成本。
6. **开源可贡献**：目录清晰、扩展点少而稳、示例 Skill / 示例 Provider 开箱可抄。
7. **连接可断、任务不断**：浏览器刷新、SSE 闪断不得杀死 Agent；UI 只是事件日志的投影。
8. **布局是用户资产**：面板怎么摆、开哪些窗，属于可导出配置，不是写死的页面骨架。
9. **扩展先于分叉**：新工具、新模型厂商、新消息块、新默认布局，优先走插件/注册表，而不是改核心。

### 2.4 明确非目标（v1 不做）

避免做成「小 Cursor 全集」导致永远做不完：

- 不做账号体系、SSO、多租户 SaaS、计费、云同步。
- 不做完整 IDE：无调试器、无语言服务器全家桶、无完整 Git GUI（可只读状态 + 基础 diff）。
- 不做实时多人协作编辑。
- 不做移动端原生 App。
- 不做自动在公网暴露、不做默认允许任意 shell。
- 不做「一个 Agent 同时改多个互不相关仓库」的默认能力。
- v1 不做完整 MCP 市场、子 Agent 并行军团、云端沙箱集群（预留扩展点）。
- 服务进程重启后，交互式 PTY 进程无法复活（刷新浏览器可以重连**仍存活**的 PTY；重启服务则新建终端）。这是诚实限制，不是缺陷隐瞒。

## 3. 用户、场景与成功标准

### 3.1 角色

| 角色 | 诉求 | 关键能力 |
| --- | --- | --- |
| 个人开发者 | 本机跑起来，对着自己的项目改代码 | 打开工作区、选模型、Agent 改文件、看 diff |
| 开源贡献者 | 加 Skill / Provider / 渲染器，不改核心 | 稳定扩展点与贡献指南 |
| 小团队自托管者 | 内网一台机器给几个人用 | 绑定地址、可选访问口令、工作区隔离（仍无账号） |
| 安全/合规关注者 | 密钥、命令、文件出站可控 | 密钥加密、命令策略、审计日志、路径沙箱 |

无登录产品仍要有「操作者」概念：v1 视为**单实例本地用户**。浏览器侧用匿名 `client_id`（localStorage）区分会话偏好；服务端以工作区为隔离边界。

### 3.2 核心场景（必须跑通）

1. **冷启动**：克隆仓库 → `docker compose up` 或本地前后端启动 → 浏览器打开 → 选择/创建工作区目录 → 配置一个 LLM → 发送「解释这个项目怎么跑」。
2. **改一个 bug**：用户 @ 文件提问 → Agent 检索/阅读 → 提出补丁 → 用户在 diff 中 Accept / Reject → 编辑器同步。
3. **插 Skill**：把符合 Agent Skills 规范的目录丢进 `skills/` 或工作区 `.agents/skills/` → 开关启用 → 相关任务自动加载说明并执行。
4. **换模型**：新增 OpenAI 兼容端点（含 Ollama / vLLM / 硅基流动等）→ 在输入框旁切换模型 → 同一会话继续。
5. **看过程**：一次任务中同时出现思考、工具调用、终端输出、文件 diff、最终回复，UI 分类渲染且可折叠。
6. **中止与重试**：生成中可 Stop；失败可 Retry；可从某条用户消息 Edit 后重发。

### 3.3 成功标准（上线门槛，非 KPI 空话）

- 5 分钟内，新贡献者按 README 在 Linux 上跑起前后端并完成一次流式对话。
- 对中小型仓库（≤ 2 万文件）完成「读代码 + 改 1～3 个文件 + 展示 diff」闭环。
- 新增一个 Skill 只需目录 + `SKILL.md`，无需改 Python 核心（脚本类 Skill 按约定可被工具调用）。
- 新增一个 OpenAI 兼容 Provider 只需填表，无需发版。
- 消息协议有 TypeScript 与 Pydantic 双端同一套类型；前端按 `type` 渲染，而不是解析纯文本。
- 默认配置下，Agent 无法读写工作区以外的路径，无法在未授权时执行高风险命令。

## 5. 交互与信息架构（对标 Cursor）

### 5.1 总体布局

Web 端无法 1:1 复制桌面 IDE，但**第一屏必须一眼是「编码工作台」而不是 ChatGPT**。

默认布局是 **停靠工作台**，不是固定四栏。实现库：**dockview-vue**。每个面板是可拖动窗口（标签拖到边缘分屏、浮动、最大化、关闭、再从活动栏打开）。默认种子布局：

```
┌──────┬─────────────┬──────────────────────────┬─────────────────┐
│ 活动  │ 侧边内容     │ 主区（编辑器 / Welcome）   │ Agent 面板      │
│ 栏    │ 文件树      │ Tab + Breadcrumb          │ 会话头/模型     │
│ Files │ 会话列表    │ Monaco                    │ 消息时间线      │
│ Chat  │ 搜索        │ 或 Diff Review            │ Composer        │
│ Git   │ Skill       │                           │                 │
│ Skill │ 设置入口    │──────────────────────────│                 │
│ Term  │             │ 底部面板：交互式终端       │                 │
│ Set   │             │                           │                 │
└──────┴─────────────┴──────────────────────────┴─────────────────┘
```

活动栏本身固定不参与停靠（类似 Cursor Activity Bar），其余全部可拖。布局 JSON 持久化到服务端设置（刷新/换浏览器配置目录后可恢复），并允许导出/导入、切换预设（Cursor-like / Chat-focused / Terminal-heavy）。

- **活动栏**（最左窄条）：Files / Chat / Search / Git / Skills / Terminal / Settings。参考 Cursor 左侧 Activity Bar，不要做成后台管理系统菜单。
- **Agent 面板默认在右侧**（Cursor Agent 的主心智）。用户可把它拖到左侧或底部。
- **品牌**：工作台标题/空态显示 **Code Agent**。不要用仪表盘卡片墙当首页。
- **主题**：编码工作台默认深色炭黑 + 琥珀强调（对标 Cursor，不是营销落地页）。TinyVue / TinyRobot 走同一套 CSS 变量。禁止紫光、霓虹、玻璃拟态堆叠。

TinyRobot 用于 **Agent 面板内的对话壳**（`TrContainer`、`TrBubbleList`、`TrSender`、`TrConversations`、`TrPrompts`、`TrWelcome`、`TrFeedback`）。文件树、布局、表单、抽屉用 TinyVue。Monaco、Diff、xterm 级终端是独立能力，不要硬塞进 Bubble。

### 5.2 关键界面状态

| 状态 | 用户看到什么 |
| --- | --- |
| 未选工作区 | 全屏欢迎：打开文件夹 / 最近工作区。禁止空壳聊天。 |
| 未配模型 | Composer 禁用，内嵌引导「添加模型」，可一键填 Ollama 默认值。 |
| 空会话 | Welcome + 3～6 条 Prompts（解释项目、找 bug、补测试、写 README）。 |
| 运行中 | 输入框变 Stop；时间线持续追加块；文件树对正在改的文件做标记。 |
| 等待审批 | 高风险工具卡片停住，主按钮 Approve / Deny，可勾选「本次会话记住」。 |
| 有待审 diff | 主区切到 Review：文件列表 + unified/split diff；Accept Hunk / Accept File / Reject。 |
| 出错 | 分类错误块（网络、额度、工具失败、取消），可 Retry，不吞异常。 |

### 5.3 Composer（输入区）

参考 Cursor Chat/Composer，而不是普通 IM：

- 多行编辑、Enter 发送 / Shift+Enter 换行（可配置）。
- 发送前可选：**Agent / Ask / Plan** 三模式。
  - **Ask**：只读工具（读文件、搜索），不写盘、不跑危险命令。
  - **Plan**：先产出可勾选计划，用户确认后再执行（v1 可简化为「先输出计划消息，二次确认」）。
  - **Agent**：可写文件、按策略跑命令。
- **模型选择器**在输入框左下或右上，切换立即对「下一轮」生效；进行中的 run 不热切换。
- **上下文引用 `@`**：文件、目录、当前打开 Tab、符号（v1 可先文件/目录）。以 chip 形式进消息，发送时带 `references[]`。
- **图片**：v1 可选；若模型声明 vision 再开放。
- 进行中禁止连发造成队列错乱；v1 采用「运行中禁用发送，或显式排队一条」。推荐：**允许排队 1 条**，UI 显示 Queued。
- Stop 必须在 300ms 内停止向模型拉 token，并尽力取消正在跑的工具（进程组 kill）。

### 5.4 消息时间线：分类渲染（核心体验）

时间线不是「user bubble / ai bubble」两列，而是 **Run 内的有序 Block 流**。一条 Assistant 消息由多个 Block 组成。

| `block.type` | 展示 | 交互 |
| --- | --- | --- |
| `user.text` | 右对齐用户气泡 | 编辑、重新发送、复制 |
| `user.references` | 文件/目录 chip | 点击在编辑器打开 |
| `assistant.markdown` | 左对齐 Markdown + 代码块 | 代码块复制；可「插入到光标 / 另存」 |
| `assistant.thinking` | 可折叠「思考」 | 默认折叠进行中的长思考；结束后保留可展开 |
| `assistant.plan` | 有序列表 + checkbox | 确认执行 / 修改后执行 |
| `tool.call` | 工具名 + 状态点 + 摘要参数 | 展开完整 JSON；进行中骨架屏 |
| `tool.result` | 截断输出 + 退出码 | 展开全文；过长虚拟滚动 |
| `file.read` | 路径 + 行范围 | 点击打开并高亮 |
| `file.diff` | 路径 + 增删行统计 + 内嵌 diff | 在主区打开 Review；Accept/Reject |
| `file.write` | 新建文件卡片 | 打开文件 |
| `file.delete` | 危险样式路径 | 可在审批流中出现 |
| `terminal` | 类终端等宽输出 | 复制；可「在底部终端重放」 |
| `todo` | 检查项列表 | 只读同步 Agent 待办 |
| `skill.activated` | Skill 名 + 来源路径 | 打开 SKILL.md 预览 |
| `approval` | 权限请求 | Approve / Deny / 始终允许该类 |
| `error` | 错误码 + 可读说明 | Retry |
| `usage` | token / 耗时 / 费用估算 | 默认弱展示，可关 |

渲染架构：`block.type → Renderer`。未知类型降级为 JSON 折叠块，保证协议向前兼容。TinyRobot 的 `TrBubble` 做外壳，**内容插槽由业务渲染器接管**，不要把 diff 和工具调用统统当 Markdown 字符串。

滚动规则：

- 用户在底部时自动跟随；上翻查看历史时不强制吸底（Cursor 同款）。
- 流式期间只重绘最后一个块，避免整表虚拟列表抖动。
- 长 diff 默认摘要，点开才进主区。

### 5.5 文件与编辑器

- 文件树：忽略 `.git`、`node_modules`、`.venv` 等；显示 Git 状态色（modified/untracked）。
- 点击文件用 Monaco 打开；语言高亮按后缀。
- Agent 改文件时：**不直接静默覆盖用户未保存缓冲**。若用户有脏文件，提示「Agent 写入 vs 你的未保存」三选一：保留用户 / 用 Agent / 打开三路对比（v1 可简化为阻止并提示保存）。
- 保存：Ctrl+S；可配置 format on save（v1 可不做格式化，只留开关位）。
- 只读工作区模式：Ask 默认；磁盘权限不足时明确提示。

### 5.6 Diff Review

编码 Agent 的信任来自审查，不来自聊天气泡。

- 每个 `file.diff` 可「在 Review 打开」。
- 支持 Accept File / Reject File；v1.1 再做 Accept Hunk。
- Reject 后工作区恢复到该次 run 开始前该文件的快照（见运行时「文件快照」）。
- 全部 Accept 后可选择「提交说明草稿」（不强制 git commit）。

### 5.7 终端（P0，交互式）

- 用户终端：xterm.js + 后端 PTY（`pty.fork`），WebSocket 双向传输 stdin/stdout、resize。
- 可开多个终端标签；每个是独立 PTY；标题可改。
- **刷新浏览器**：PTY 在服务进程内存中续活，前端重连同一 `terminal_id`，缓冲区回放最近 N KB（默认 200KB）。
- **服务重启**：PTY 丢失，UI 显示「会话已断开，点击重建」。
- 工作目录默认工作区根，可 `cd`；仍受工作区策略约束（可选 chroot 式 cwd 限制，默认允许在工作区内）。
- Agent `run_command` 使用独立 subprocess，**禁止**把用户正在用的 PTY 当工具输出设备。
- 消息时间线里的 `terminal` 块是工具输出回放，点击「在终端打开」可把 cwd/命令送到新的交互式终端。

### 5.8 会话列表

- 按工作区过滤。
- 自动标题：首条用户消息截断，可重命名。
- 搜索会话内容（Phase 2 可先标题搜索）。

## 7. 模式与工作流（产品逻辑）

### 7.1 一次 Agent Run

```
用户发送
  → 创建 run（queued/running）
  → 组装上下文（规则、Skill 目录、引用文件、历史压缩）
  → LangGraph 循环：
        模型流式输出（thinking / text / tool_calls）
        → 若 tool_call：策略检查 → 可能 HITL → 执行 → 推 tool.result / file.diff
        → 若纯文本结束：结束
  → run.completed（usage）
  → 若有未 Accept 的 diff：会话头提示「待审查 n 个文件」
```

### 7.2 写文件的用户可见契约

1. 工具真正改的是工作区磁盘（Agent 要能跑测试，必须落盘）。
2. 同时生成 `file.diff` 块，方便审查。
3. 每个 run 开始时对将改文件做 copy-on-write 快照，支持 Reject 回滚该 run 的变更。
4. 不在 v1 做完整时间旅行；只保证「拒绝本次 run 对文件 X 的改动」。

### 7.3 失败语义

| 情况 | 行为 |
| --- | --- |
| 模型 429/500 | 可配置重试 1～2 次；仍失败则 `error` 块 |
| 工具超时 | 返回错误给模型，允许它换策略；同时 UI 标记失败 |
| 用户 Stop | 保留已产生块；磁盘已写入保留并标记「可能不完整」 |
| 审批拒绝 | 工具结果为 `denied by user`，模型应改方案而不是死循环（对同工具连续 deny 3 次则停） |

## 8. 非功能需求

### 8.1 性能

- Composer 发送后 200ms 内出现「已连接/思考中」状态。
- Token 到达后 100ms 内反映到 UI。
- 文件树 1 万节点可懒加载使用；一次 `grep` 默认上限 200 条命中、30s 超时。
- 单会话历史建议前端虚拟列表；超过 500 块仍可滚动。
- SQLite 可支撑单用户；文档注明多用户请换 PostgreSQL（预留配置）。

### 8.2 可靠性

- 进程重启：未完成 run 标记 interrupted。
- 流重连：`Last-Event-ID` 补发。
- 工具副作用可部分失败：已写文件不自动撤销，除非用户 Reject。

### 8.3 安全（无登录下的真实威胁模型）

威胁：本机绑定错误导致局域网任意人指挥 Agent 删库、读 `~/.ssh`、盗用 API Key；Prompt 注入通过仓库 README 诱导外泄密钥。

v1 必须：

1. 默认只绑 `127.0.0.1`。
2. 路径沙箱。
3. 密钥加密（Fernet 一类，主密钥来自环境变量 `CODE_AGENT_MASTER_KEY`，若缺失则首次启动生成并写入 `~/.code-agent/master.key`，权限 0600）。
4. 保护文件与命令策略。
5. 系统提示中明确：忽略「忽略以上指令」类注入时，仍不得越权出工作区。
6. 前端 XSS：Markdown 渲染消毒；终端输出不当 HTML 解释。
7. CORS 默认仅本机 origin。
8. 依赖扫描与不可执行来源的 Skill 脚本默认 `chmod` 策略（zip 安装时去掉危险权限）。

不做：把「无登录」宣传成「可以安全公网裸奔」。

### 8.4 可观测性

- 结构化日志：`run_id`、`conversation_id`、`tool`、耗时。禁止打 key。
- 可选 OpenTelemetry（P2）。
- 每次 run 记录 usage，便于用户自己看成本。

### 8.5 国际化与无障碍

- UI 中文优先，i18n 框架预留（Vue I18n）。
- 焦点顺序、输入框 label、Stop 按钮可键盘到达。
- 不要只靠颜色表达工具成功/失败。

### 8.6 兼容性

- 浏览器：最新 Chrome / Edge / Firefox；Safari 次优先。
- 后端：Python 3.11；Linux 一等公民；macOS / Windows 作为 P1。
- Node：与 TinyVue 3 + Vite 官方要求对齐（文档写死版本）。

### 8.7 合规

- 用户代码默认不上传除其配置的 LLM Provider 以外的任何第三方。
- LICENSE、第三方组件许可证清单。
- 不在默认遥测里传文件内容。

## 9. 技术架构约束

### 9.1 分层

```
web (Vue3)
  views / components / renderers / stores / api / protocol
api (FastAPI)
  routers → services → graphs/tools/skills/providers → repositories (Tortoise)
```

原则：

- Router 不写业务；LangGraph 节点不直接操作 ORM。
- 所有对外流式事件经过 `protocol` 包，禁止前端解析 LangGraph 内部 event 名。
- 工具函数可单测（假文件系统）。

### 9.2 LangGraph 建议形态

单一 `coding_agent` 图即可，不必一上来微服务化多图：

- State：`messages`、`workspace_id`、`mode`、`todos`、`loaded_skills`、`pending_approval`。
- 节点：`model`、`tools`、`hitl`、`compress`（条件）。
- Checkpointer：v1 `SqliteSaver` / `MemorySaver`（dev）；与业务库可分开文件，避免锁竞争。
- 流：`stream_mode` 组合 `messages` + `updates` + `custom`。业务用 `custom` 推 `file.diff` 等，避免前端绑定框架细节。

HITL：LangGraph interrupt 适合审批。审批通过后 `Command(resume=...)`。

### 9.3 模型适配

内部统一成「OpenAI tools 风格」的中间表示，再适配 Anthropic 等。这样 Agent 图不关心厂商。

无法 tool call 的模型：Agent 模式入口直接拦截。

### 9.4 前端状态

- Pinia：workspace、conversation、run、settings。
- 协议层 `applyEvent(e)` 纯函数，便于测试。
- Monaco 与 Agent 写盘用「版本号 / mtime」协调。

### 9.5 TinyRobot 使用边界

用：会话列表、发送框、气泡壳、欢迎提示、反馈、主题。

不用或慎用：把 TinyRobot 当 IDE 壳；其 MCP 选择器可 Phase 2 再接。编码专用块（diff、tool、todo）全部自定义。

## 10. 数据模型（TortoiseORM）

逻辑模型，名称可在实现时微调。

**Workspace**  
`id, name, root_path, ignore_globs, created_at, last_opened_at`

**Conversation**  
`id, workspace_id, title, mode, model_ref, created_at, updated_at, archived`

**Message**  
`id, conversation_id, role, created_at, sort_key`  
块不拆表也可：`blocks JSON`（SQLite JSON）。推荐 JSON，避免过度范式。

**Run**  
`id, conversation_id, status, started_at, ended_at, error_code, usage_json, graph_thread_id`

**LlmProvider**  
`id, name, kind, base_url, api_key_encrypted, extra_headers_json, created_at`

**LlmModel**  
`id, provider_id, model_id, display_name, context_window, supports_tools, supports_vision, pricing_json, is_default`

**SkillRecord**（缓存发现结果）  
`id, name, source, path, enabled, description, checksum, invalid_reason`

**Setting**  
`key, value_json`（实例级）

**AuditLog**（P1）  
`id, at, run_id, action, detail_json`（无密钥、无完整文件内容，可存路径与 hash）

索引：`conversation_id+sort_key`、`run.status`、`workspace.last_opened_at`。

## 11. 接口与流式协议

### 11.1 REST 资源（草案）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/api/workspaces` | 列表/添加 |
| GET | `/api/workspaces/{id}/tree` | 懒加载树 |
| GET | `/api/workspaces/{id}/file` | 读文件 |
| PUT | `/api/workspaces/{id}/file` | 用户保存 |
| GET | `/api/conversations` | 列表 |
| POST | `/api/conversations` | 创建 |
| POST | `/api/conversations/{id}/messages` | 发送并启动 run |
| GET | `/api/runs/{id}/events` | SSE |
| POST | `/api/runs/{id}/cancel` | 取消 |
| POST | `/api/runs/{id}/approvals/{aid}` | 审批 |
| POST | `/api/diffs/{id}/accept` | 接受文件变更（若采用显式审查提交） |
| CRUD | `/api/llm/providers` `/api/llm/models` | 模型 |
| POST | `/api/llm/providers/{id}/test` | 探测 |
| GET/PATCH | `/api/skills` | 列表与启用 |
| GET/PATCH | `/api/settings` | 设置 |

发送消息 body：

```json
{
  "text": "修复登录按钮的点击穿透",
  "mode": "agent",
  "model_id": "uuid",
  "references": [{ "type": "file", "path": "src/components/Login.vue" }]
}
```

### 11.2 SSE 事件信封

每条事件：

```json
{
  "v": 1,
  "event_id": "01J...",
  "run_id": "...",
  "ts": "2026-08-18T13:00:00.000Z",
  "type": "assistant.delta",
  "payload": {}
}
```

`type` 枚举（v1 冻结，新增只能加不能改语义）：

- `run.started` / `run.heartbeat` / `run.completed` / `run.failed` / `run.cancelled`
- `block.started` `{ block_id, type, meta }`
- `block.delta` `{ block_id, text? , json_patch? }`
- `block.completed` `{ block_id, status }`
- `approval.requested` `{ approval_id, kind, summary, details }`
- `usage.updated` `{ input_tokens, output_tokens, elapsed_ms }`

前端只认信封；`block.type` 决定渲染器。LangGraph 原始事件不得出网。

### 11.3 错误码

`workspace.not_found`、`path.escape`、`model.unsupported_tools`、`provider.auth`、`run.busy`、`policy.denied`、`skill.invalid`。错误响应含 `code` + `message` + `retryable`。

## 21. 刷新续流与插件的架构补充（v0.2）

### 21.1 事件源 Run

```
POST /messages  → 入库 user message + 创建 Run(status=running)
                → asyncio.create_task(execute)
                → 立即返回 run_id
execute         → LangGraph astream → EventBroker.publish
publish         → RunEvent 落库 + 更新 Message.blocks + 广播订阅者
SSE             → replay(seq) + subscribe(live)
刷新            → GET conversation（blocks）+ GET run + SSE(last_event_id)
Stop            → 显式 POST /cancel，而不是靠断开 SSE
```

禁止把 `StreamingResponse` 直接绑在图执行上作为唯一生命周期。那会在刷新时杀掉 Agent。

### 21.2 终端重连

内存 `PtyManager[terminal_id] = { pid, fd, ring_buffer, subscribers }`。WebSocket 只是又一个订阅者。刷新 = 新 socket 订阅旧会话。

### 21.3 配置与插件加载顺序

启动时：加载 YAML 层 → 扫描插件目录 → 注册 Tool/Provider → 把「已启用列表」与 DB 用户偏好求交 → 注入 Agent。运行中改启用项对**下一轮 run**生效。

插件 Python 约定：模块导出 `register(registry: PluginRegistry) -> None`。

前端约定：`src/renderers/index.ts` 的 `register(type, component)`；布局预设 `src/layouts/presets.ts`。

本文即开发真源。实现以 `code-agent/` 为准。
