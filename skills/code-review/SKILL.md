# 代码审查

## 指令

1. 先读取 diff 和相关上下文，确认变更目标、影响范围及现有约定。
2. 按严重程度检查：功能错误、数据丢失、权限绕过、注入风险、兼容性回归、性能问题和可维护性风险。
3. 每个发现都给出文件和行号、触发条件、实际影响及可行修复方向。
4. 区分确定性问题与需要确认的假设，不把风格偏好当作缺陷。
5. 检查测试是否覆盖主路径、错误路径、边界条件和跨模块契约。
6. 结论先列 findings，再列假设、测试状态和简短变更摘要。

## 约束

- 不因为代码风格或个人偏好提出低价值意见。
- 不修改代码，除非用户明确同时要求修复发现的问题。
- 不泄露敏感配置、凭据或用户数据。
