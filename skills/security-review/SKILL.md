# 安全审查

## 指令

1. 读取 diff 与相关上下文（调用链、配置、依赖）。
2. 按严重程度检查：
   - **注入**：SQL、命令、路径、模板、XSS
   - **鉴权**：越权访问、缺失校验、IDOR
   - **敏感数据**：密钥硬编码、日志泄露、错误信息暴露
   - **依赖**：已知漏洞版本、不可信来源
   - **加密与传输**：弱算法、明文存储、缺失 HTTPS 假设
3. 每个 finding 给出：严重程度、文件:行号、触发条件、影响、修复方向。
4. 区分确定漏洞与需确认的假设。
5. 输出 findings 表格，再附测试建议与变更摘要。

## 严重程度

| 级别 | 含义 |
| --- | --- |
| Critical | 可直接被利用，需立即修复 |
| High | 高概率风险或影响大 |
| Medium | 需特定条件才可利用 |
| Low | 防御纵深或最佳实践缺口 |

## 约束

- **只审查，不修改代码**，除非用户明确要求修复。
- 不把风格问题当安全缺陷。
- 不在输出中复述密钥、令牌、PII。
