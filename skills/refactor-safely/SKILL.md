# 安全重构

## 指令

1. **先理解再动刀**：读调用方、测试、类型定义，确认当前行为契约。
2. **小步提交**：每次只做一个重构意图（提取 / 重命名 / 搬移 / 简化）。
3. **保持行为等价**：不改 public API 语义，除非用户明确要求。
4. **测试护航**：重构前后跑相关测试；无测试时至少跑 typecheck/lint。
5. **重命名**：全局搜索引用，一并更新 import、字符串 key、文档。
6. 完成后简述：改了什么、为何更安全/可读、跑了哪些验证。

## 允许

- 提取函数/组件/模块
- 消除重复（DRY）
- 改善命名与文件组织
- 简化条件与早期返回

## 禁止

- 顺手加新功能或改业务逻辑
- 大范围重写无测试覆盖的模块
- 删除用户未提及的代码
- 用 `@ts-ignore` / 空 catch 掩盖问题

## 大重构时

若影响 >5 文件或公共 API，先列出计划并请用户确认再继续。
